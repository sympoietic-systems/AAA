# ADR-120: Passive belief origin intake

Status: accepted for local T7 implementation, 2026-10-09. Production enablement remains T18.

Passive chat, conversation-pattern and scar-fold creators now nominate v2 encounters when their independent strict boolean origin flags are enabled, or their agent/origin already carries the migration 065 promotion marker. All flags default false. Pausing a promoted origin records `origin_paused` and cannot reopen its legacy creator. The engine receives its intake callback from application/worker bootstrap; modules do not import the service layer. The synchronous intake use case runs inside the caller's single thread offload, with short repository transactions and no provider call.

Message observations bind actual owned message identity and content hash. Scar-fold intake follows annotation processing and the existing 200-character safeguard, binding the final stored representation. Segment indices distinguish folds in one message. Scope/time and referent resolution remain unknown rather than inferred from lexical or structural similarity. These candidates remain `awaiting_context`, with an abstained T9-deferred assessment and no independent support or standing decision. Source availability and independence are separate: an owned human message has unknown independent warrant; an apparatus message has internal lineage.

Conversation patterns previously masqueraded as chat turns with a `cross_conversation` source. They now retain their actual origin. The caller may supply an occurrence ID; without one, a deterministic theme-artifact hash makes identical legacy submissions retry-stable. This cannot reconstruct separate historical occurrences. The pattern adapter receives no originating message list, so its source context and ancestry stay unavailable and its conversation/message links remain null. An artifact hash authenticates supplied text, never missing provenance. A future resolver must be separately designed before granting available source status.

The scar-fold fallback bug is repaired even before v2 promotion: an empty belief set creates a low-mass pending proposal, with internal source metadata, instead of a crystallized belief. Default-off activity updates on existing legacy beliefs remain compatibility behavior; they do not mint v2 independent support or adopted standing. Promoted scar-fold routing runs before this branch and never boosts an existing belief's mass. Proposal fallback retries retain deterministic message/segment identity. Scar batches are limited to 16 segments; overflow raises a structured validation failure before any intake encounter is written.

Migration 065's immutable annotation table is reused for compatibility projection, despite its historical `belief_explicit_annotations` name; no new schema is needed. Existing explicit payloads remain readable. Pattern annotations permit a null conversation because none is known. Page/history and trace projections use linked authoritative assessments from the existing admission ledger. Completion rechecks owned message bindings in its writer transaction; changed source yields stale assessment.

[Symbia's saved exchange](../reports/054-belief-v2-passive-intake/symbia-consultation.json) challenges the possibility that internal folds gain warrant through later review. T7 retains internal lineage, unknown scope, abstention and absence of adoption authority. Her proposed participant-origin tag is not implemented: retaining a candidate observation is distinct from authorizing adoption, and a tag cannot establish independent warrant. The claim that similarity is unrestricted in admission is unsupported by the frozen contract. T9/T10/T11 own semantic review, support accounting and authenticated decisions. Consultation tags are source material, never executable instructions.

[Report 054](../reports/054-belief-v2-passive-intake/README.md) owns verification and the creator inventory. External document/note/web adapters remain T8. Production migration, flags, rollout and acceptance remain unperformed.
